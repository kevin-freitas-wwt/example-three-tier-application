# w00t — UI & API Polish (all 7 improvements)

## Goal
Deliver a noticeably better to-do UI in one cohesive pass: fix the stale metadata, make every interactive element keyboard-accessible, add missing delete functionality end-to-end, liven up the empty state, let users filter tasks, get instant feedback when adding a task, and enable clicking a title to rename it in place.

---

## Tasks

### 1 — `src/api/index.js` · Add DELETE endpoint
Add a new route immediately after the PATCH handler:
```
DELETE /tasks/:id
```
- Parse `id` as integer.
- `DELETE FROM tasks WHERE id = $1`.
- If 0 rows deleted → 404 `{ error: 'Not found' }`.
- If deleted → 204 No Content (empty body).

---

### 2 — `src/web/app/actions.ts` · Add deleteTask + updateTaskTitle server actions
```ts
export async function deleteTask(id: number): Promise<void>
export async function updateTaskTitle(id: number, title: string): Promise<void>
```
- `deleteTask` calls `DELETE /tasks/:id`, then `revalidatePath('/')`.
- `updateTaskTitle` calls `PATCH /tasks/:id` with `{ title }`, then `revalidatePath('/')`.
- Guard `updateTaskTitle`: skip the fetch if `title.trim()` is empty or unchanged.

### 4 — `src/web/app/TaskList.tsx` · New Client Component (the bulk of the work)
`'use client'` at the top. Receives `initialTasks: Task[]` as a prop.

#### 4a — Optimistic add
- Wrap the component body with `useOptimistic` seeded from `initialTasks`.
- The add-form calls a `handleAdd` async function that:
  1. Calls `addOptimisticTask({ id: -Date.now(), title, completed: false, created_at: '' })` immediately.
  2. Clears the controlled input (`useState` for the input value) immediately.
  3. Awaits `createTask(formData)` (existing server action).
- The pending optimistic row renders with 50 % opacity to signal in-flight status.

#### 4b — Filter tabs
- `useState<'all' | 'active' | 'completed'>` defaulting to `'all'`.
- Render three pill buttons (All / Active / Completed) above the task list.
- Derive `visibleTasks` by filtering the optimistic list.
- The active tab button gets a filled background; inactive tabs are outlined.
- Hide the tabs entirely when the list is empty.

#### 4c — Delete button
- Each task row gets a `×` button on the far right.
- Clicking calls `deleteTask(task.id)` (server action, no extra form needed — call directly from a `button onClick` with `startTransition`).
- Button is `aria-label="Delete task"`, styled as a small muted `×` that turns red on hover.

#### 4d — Visible focus ring on checkbox button
- Add `focus-visible:ring-2 focus-visible:ring-zinc-500 focus-visible:ring-offset-2` to the checkbox `<button>` className (replacing the bare `focus:outline-none` approach currently implicit).

#### 4e — Inline title edit
- Each task has local state `editing: boolean`.
- When `editing` is false: render `<span>` as before; on click → set `editing = true`.
- When `editing` is true: render `<input>` pre-filled with `task.title`, auto-focused.
  - On `Enter` or `onBlur`: if title changed and non-empty, call `updateTaskTitle(task.id, newTitle)` in a `startTransition`; then `setEditing(false)`.
  - On `Escape`: reset to original title, `setEditing(false)`.
- Completed tasks are not editable (clicking them does nothing / span stays struck-through).

#### 4f — Empty-state illustration
Replace the plain `<li>` text with:
```tsx
<li className="flex flex-col items-center gap-3 py-12 text-zinc-400 select-none">
  {/* inline SVG clipboard or large emoji */}
  <span className="text-5xl" aria-hidden="true">📋</span>
  <span className="text-sm">No tasks yet. Add one above!</span>
</li>
```
Show this only when `visibleTasks.length === 0` (not the raw list length, so the empty-state also shows when a filter matches nothing).
